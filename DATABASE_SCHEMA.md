# AI CareerPilot — Database Schema & Supabase Configuration Guide

This document details the database architecture, table definitions, relationships, Row Level Security (RLS) policies, and Supabase project configuration instructions for **AI CareerPilot**.

---

## 1. Quick Setup in Supabase

1. **Create a Supabase Project:**
   - Log in to your [Supabase Dashboard](https://supabase.com/dashboard).
   - Click **New Project**, select an organization, name it `ai-careerpilot`, and choose a secure database password.

2. **Run the Database Migrations:**
   - Navigate to the **SQL Editor** tab in the Supabase dashboard.
   - Run the contents of `supabase/migrations/20240101000000_init_schema.sql`.
   - Run the contents of `supabase/migrations/20240101000001_rls_policies.sql`.

3. **Configure Storage Bucket for Resumes:**
   - Go to **Storage** -> **New Bucket**.
   - Name the bucket `resumes`.
   - Set bucket visibility to **Private**.
   - Under bucket policies, allow authenticated users to upload and view files where the folder/path matches their user ID:
     ```sql
     CREATE POLICY "User resume upload" ON storage.objects
     FOR INSERT TO authenticated
     WITH CHECK (bucket_id = 'resumes' AND auth.uid()::text = (storage.foldername(name))[1]);

     CREATE POLICY "User resume select" ON storage.objects
     FOR SELECT TO authenticated
     USING (bucket_id = 'resumes' AND auth.uid()::text = (storage.foldername(name))[1]);
     ```

4. **Copy API Credentials to `.env.local`:**
   - In Supabase, go to **Project Settings** -> **API**.
   - Copy **Project URL** into `NEXT_PUBLIC_SUPABASE_URL`.
   - Copy **anon public key** into `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
   - Copy **service_role secret** into `SUPABASE_SERVICE_ROLE_KEY`.

## 2. Table Specifications & Relationships

### 1. `profiles`
*Linked 1:1 with Supabase `auth.users` via trigger.*
- `id` (UUID, Primary Key, references `auth.users.id` ON DELETE CASCADE)
- `full_name` (TEXT)
- `email` (TEXT)
- `avatar_url` (TEXT)
- `education_level` (TEXT, default: "Bachelor's Degree")
- `current_role` (TEXT, default: "Student / Job Seeker")
- `years_of_experience` (INTEGER, default: 0)
- `created_at` (TIMESTAMPTZ)
- `updated_at` (TIMESTAMPTZ)

### 2. `career_goals`
*Target job trajectory and learning preferences.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `target_role` (TEXT, e.g. "Full Stack Developer", "AI/ML Engineer")
- `target_industry` (TEXT, default: "Technology")
- `target_timeline_months` (INTEGER, default: 6)
- `daily_learning_minutes` (INTEGER, default: 60)
- `is_active` (BOOLEAN, default: true)
- `created_at`, `updated_at` (TIMESTAMPTZ)

### 3. `user_skills`
*Granular catalog of candidate skills.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `skill_name` (TEXT)
- `category` (TEXT, 'technical' | 'soft' | 'tool')
- `proficiency` (TEXT, 'beginner' | 'intermediate' | 'advanced')
- `verified_score` (INTEGER, 0-100)
- `source` (TEXT, 'manual' | 'resume_extract' | 'test')
- `created_at` (TIMESTAMPTZ)

### 4. `resumes`
*Uploaded candidate resumes.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `file_name` (TEXT)
- `file_path` (TEXT)
- `file_size_bytes` (INTEGER)
- `raw_text` (TEXT)
- `created_at` (TIMESTAMPTZ)

### 5. `resume_analysis`
*Structured Gemini AI resume audit and ATS heuristics.*
- `id` (UUID, PK)
- `resume_id` (UUID, FK -> `resumes.id`)
- `user_id` (UUID, FK -> `profiles.id`)
- `overall_score` (INTEGER, 0-100)
- `ats_compatibility_score` (INTEGER, 0-100)
- `parsed_info` (JSONB)
- `technical_strengths` (JSONB)
- `missing_skills` (JSONB)
- `experience_critique` (JSONB)
- `project_critique` (JSONB)
- `improvement_recommendations` (JSONB)
- `suggested_roles` (JSONB)
- `actionable_next_steps` (JSONB)
- `created_at` (TIMESTAMPTZ)

### 6. `career_roadmaps`
*Structured learning curricula generated by Gemini.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `target_role` (TEXT)
- `difficulty_level` (TEXT)
- `estimated_weeks` (INTEGER)
- `total_stages` (INTEGER)
- `current_stage` (INTEGER)
- `completion_percentage` (INTEGER, 0-100)
- `created_at`, `updated_at` (TIMESTAMPTZ)

### 7. `roadmap_tasks`
*Actionable tasks belonging to each roadmap stage.*
- `id` (UUID, PK)
- `roadmap_id` (UUID, FK -> `career_roadmaps.id`)
- `stage_number` (INTEGER, 1..3)
- `stage_name` (TEXT)
- `title` (TEXT)
- `description` (TEXT)
- `task_type` (TEXT, 'skill' | 'resource' | 'exercise' | 'project')
- `resource_url` (TEXT)
- `estimated_hours` (INTEGER)
- `is_completed` (BOOLEAN)
- `completed_at` (TIMESTAMPTZ)
- `created_at` (TIMESTAMPTZ)

### 8. `mock_interviews`
*Simulated interview sessions.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `job_role` (TEXT)
- `interview_type` (TEXT, 'technical' | 'hr' | 'behavioral' | 'mixed')
- `difficulty` (TEXT, 'entry' | 'mid' | 'senior')
- `total_questions` (INTEGER)
- `completed_questions` (INTEGER)
- `overall_score` (NUMERIC(5,2))
- `overall_feedback` (JSONB)
- `status` (TEXT, 'in_progress' | 'completed' | 'abandoned')
- `created_at`, `completed_at` (TIMESTAMPTZ)

### 9. `interview_answers`
*Per-question candidate answers and AI STAR scoring.*
- `id` (UUID, PK)
- `interview_id` (UUID, FK -> `mock_interviews.id`)
- `question_number` (INTEGER)
- `question_text` (TEXT)
- `question_category` (TEXT)
- `user_answer` (TEXT)
- `score` (NUMERIC(5,2))
- `strengths` (TEXT)
- `weaknesses` (TEXT)
- `suggested_star_answer` (TEXT)
- `metrics` (JSONB)
- `created_at` (TIMESTAMPTZ)

### 10. `project_recommendations`
*Curated hands-on project concepts.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `title` (TEXT)
- `category` (TEXT, 'beginner' | 'intermediate' | 'advanced' | 'hackathon' | 'portfolio')
- `target_role` (TEXT)
- `problem_statement` (TEXT)
- `description` (TEXT)
- `tech_stack` (JSONB)
- `key_features` (JSONB)
- `estimated_hours` (INTEGER)
- `difficulty_level` (TEXT)
- `learning_outcomes` (JSONB)
- `implementation_steps` (JSONB)
- `future_improvements` (JSONB)
- `is_bookmarked` (BOOLEAN)
- `status` (TEXT, 'suggested' | 'in_progress' | 'completed')
- `created_at` (TIMESTAMPTZ)

### 11. `user_progress`
*Historical tracking of readiness, completed tasks, and mock hours.*
- `id` (UUID, PK)
- `user_id` (UUID, FK -> `profiles.id`)
- `log_date` (DATE)
- `readiness_score` (INTEGER, 0-100)
- `roadmap_tasks_completed` (INTEGER)
- `interview_minutes_practiced` (INTEGER)
- `projects_completed` (INTEGER)
- `created_at` (TIMESTAMPTZ)

## 3. Security & Row Level Security (RLS) Verification
- All 11 tables have RLS enabled: `ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;`.
- Default behavior: Deny all unauthenticated or foreign user access.
- Policies restrict access strictly to `auth.uid() = user_id` (or cascaded through roadmap/interview ownership).
